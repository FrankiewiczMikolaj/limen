## The design, and why it is the smaller one

- The state stays `done`. `limen land`, `continue`, the keeper, group rounds and the picture all key on `done`; a new terminal state would touch each of them, and a land gate would break "inform, do not gate" (`spec/vision.md`). `open-checks` in the job record marks the difference, and every reader that shows a done job to the coordinator says "done with open checks".
- No extra send-back. The existing before-finish note check already sends the worker back once; its answer is what Limen reads. A second round asks the same question of the same worker, and the F951 workers answered it with "Not proven yet: none" twice.
- The evidence check is mechanical: a backticked name counts when it is an existing path, or when the session surely ran it (`src/job/session-commands.ts`). Surely ran: a recorded `bash` call, answered in the same transcript by its own `bash` result with `isError: false` (both engines set it false only on exit 0); the call is one chain of simple commands joined by `&&` or a pipe; the name starts one of them; and no pipe follows it, because a pipe exits with its last command's status. Exit 0 of such a chain means each command before a `&&` and the last command of each pipe ran.
- Everything else proves nothing, and the open line names which rule held. Quoted text, comments and heredoc bodies are no commands (review 1: `echo 'npm test'`). A `;`, a line break, `||`, `&`, parentheses or backticks may skip a command (review 2: `false && npm test` after a `;`), and so may `if`, a loop, a function, `exit`, `exec`, `eval`, `source`, `trap`, `set`, `shopt`, `hash`, `enable`, `alias`, `mapfile` or `coproc` (review 3: `if true; then exit 0; fi; npm test`). `!` turns a missing command into exit 0. A command name with quotes, `\`, `$`, a glob or a brace, or one that starts with `-` (`command -p exit 0`), can run `exit`. In an OMP job, whose shell lasts for the whole session, a call after one that defines a function or runs `eval`, `source`, `.`, `trap`, `set`, `shopt`, `hash`, `enable` or `alias` proves nothing. The cost: `npm test; echo $?` and `npm test 2>&1 | tail` no longer count, so the before-finish check tells the worker the rule, and a saved log file stays valid evidence. Limen does not see functions or aliases that the shell loads at its start. Repair 4 (`repair-4.md`) added the pipe, `!`, name, result and OMP rules. Cases, each run in a real shell: `evidence/real-shell-probe.txt` and `evidence/false-positive-sweep.txt`.
- It does not judge whether the evidence proves the claim. The F951 S3 hold was marked proven with real files; at its finish only acceptance item 4, which cited a code expression, would have been flagged. The race itself was found by review, and stays a review's job.
- Old final messages cite commits and code names; those lines now read as not proven. New jobs get the line form in the before-finish check. The demo's replays of the two observed jobs run after their worktrees were pruned, so files named relative to a worktree also read as missing there; the demo says so.
